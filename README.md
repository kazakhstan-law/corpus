# Корпус законодательства Республики Казахстан

Законодательство Республики Казахстан, сложенное в систему версионирования.
Каждый акт — обычный текстовый файл, который можно открыть и прочитать, а
**каждое изменение — отдельная запись с датой** и с указанием, каким актом оно
внесено. Поэтому здесь есть не только действующий текст, но и всё, чем он был
раньше; механизм — обычный `git`.

> **Это неофициальная копия.** Официальный источник —
> Единая система правовой информации (ЕСПИ), `law.gov.kz`; ссылка на страницу
> конкретной редакции там лежит в `meta.yaml` рядом с актом.

Собрано из базы: **2026-09-16**.

## Какую часть брать

Корпус разделён на репозитории по видам актов, а решения местных органов — ещё
и по регионам: целиком он слишком велик, чтобы выкачивать его ради одного
закона. Чаще всего нужен `codes`.

- [`codes`](../../kazakhstan-law/codes) — Конституция, конституционные законы, кодексы, законы, акты Парламента и Президента, международные договоры
- [`government`](../../kazakhstan-law/government) — постановления Правительства
- [`ministerial`](../../kazakhstan-law/ministerial) — приказы ведомств
- решения местных органов, по одному репозиторию на регион:

Каждая часть самостоятельна — свой README, своя история, свой клон:

```
git clone https://github.com/kazakhstan-law/codes.git
```

## Зонтичный репозиторий

Этот репозиторий собирает все части подмодулями, и клонировать его имеет смысл
только если нужен весь корпус сразу. У этого есть две цены, о которых лучше
знать заранее: `git clone` без `--recurse-submodules` не выкачивает содержимое
вообще, а история и diff через границу репозитория не работают.

```
git clone --recurse-submodules https://github.com/kazakhstan-law/corpus.git
```

Указатель субмодуля не говорит ничего про прошлое. Истории частей расходятся —
дата, в которую в этой части ничего не менялось, не даёт в ней коммита, —
поэтому указатель это утверждение о том, где находится HEAD части сейчас, и
только.

## История переписывается

Каждая часть генерируется из базы целиком, поэтому обновление приходит не
новыми коммитами сверху, а force-push'ем: хеши меняются все. Прошлые сборки
помечены тегами `build/` и не удаляются, а клон догоняет так:

```
git fetch && git reset --hard origin/main
```
